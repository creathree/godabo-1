## ゴダボーワンとは

**参加型の 5W1H あそび** です。

- **5W1H** — だれが・いつ・どこで・なにを・なぜ・どのように
- 参加者がそれぞれ埋め、全員が揃ったら **ひとつの作品** として順に見ていく
- テレビのように **カードをめくる演出** と **ナレーション** でオチや流れを強調するイメージ

名前は 5W1H から **ゴダボーワン（ゴダボーワン）** としています。本リポジトリは、その **Web フロント** を公開開発する場所です。

---

## 企画の出発点

「作りたい」からブレインストーミングし、あとから **できること・コスト・期間** で削ぎ落とした、という進め方が note 第一回の軸です。

例として挙げていたアイデア（要約）:

| テーマ | 方向性 |
| --- | --- |
| 参加人数 | あらかじめ人数を決め、埋まったら進行できる |
| 多言語 | 日本語と語順が近い **韓国語** に対応（自社 npm [bracket-i18n](https://www.npmjs.com/package/bracket-i18n) を想定） |
| 一同鑑賞 | 全員が書き終えてから、みんなで同じ作品を見る |
| 演出 | カードを一枚ずつめくり、TTS でナレーション |
| 防衛 | ログイン＋**Middleware と Cloudflare** で水際を固める |
| 認証 | 推奨されるリダイレクト認証（ポップアップ認証は避ける） |
| 対面／オンライン | その場とリモート両方。「スピーカー役」一人だけ音を出す |

これらは **ゴールの地図** であり、すべてが第一回のコードには含まれません。順に実装していきます。

---

## 設計の姿勢

note で強調している考え方です。

1. **エコ（低コスト）** — Firebase・Cloudflare の無料枠を前提に、Room 単位で状態を束ねるなど運用コストを抑える。
2. **知っているかどうかで差が出る** — 調べて選んだ構成を使う（Durable Objects・R2・RPC などの組み合わせ）。
3. **設計の根っこを先に言語化する** — 曖昧なまま実装すると散らばるため、後の回で **TypeScript と型（Interface）** を軸に据える。
4. **完璧な初稿は不要** — 模造紙レベルでも始め、何度も直す。

詳細なインフラ図・ページ構成は note 本文と設計図を参照してください。

---

## ページ構成のイメージ（note より）

公開時は大きく **親ページ** と **Room に入った子ページ**、および **発表・めくり用のページ** など、少数の画面に収めたい、という方針です。  
プライバシー・セキュリティポリシーは認証に合わせて別途用意する想定です。
