「CDN の会社」くらいの印象で止まっている人も多いので、**なぜこのプロジェクトの土台にするか** を先に書きます。手順は [cloudflareトンネルの作り方](./cloudflareトンネルの作り方.md) へ。

## 日本ではあまり聞かない、世界では当たり前のインフラ

国内の開発現場だと、レンタルサーバや国内クラウド、あるいは超巨大クラウドの名前だけが耳に入ることもあります。**Cloudflare** は、エンジニア同士の会話や海外の記事ではもっと前面に出ています。

Cloudflare がやっていることは、ざっくり言うと **インターネットの手前（エッジ）に防御・配信・実行環境を置く** ことです。

| 観点 | ざっくりした位置づけ |
| --- | --- |
| **エッジの規模** | 世界中にデータセンター・PoP を張り、リクエストを利用者の近くで受ける。CDN だけでなく DNS・WAF・Workers などが同じ網の上にある |
| **料金の考え方** | 帯域課金の旧来型 CDN と違い、**定額に近いプラン** や **無料枠の厚さ** で小規模〜個人開発が乗りやすい設計が多い |
| **これから** | 本番をエッジに寄せる（Pages / Workers）、ゼロトラスト接続（Tunnel）、R2 など、**アプリの置き場そのもの** がエッジ側に寄っていく流れ |

正確な拠点数や価格はプランと時期で変わるので、ここでは数値の丸暗記はしなくてよいです。大事なのは **「世界中のエッジで同じ製品群が動く」** という型が、もう一般インフラの一線に入っている、ということです。

ゴダボーワンも note 第一回で書いたとおり、**Middleware と Cloudflare で水際を固める**・**無料枠を前提にエコに** という方針があります。第二回から、その第一歩として **Tunnel** をリポに組み込んでいます。

---

## 第二回から Tunnel — 開発を「本番に近い形」で見せる

**Cloudflare Tunnel**（`cloudflared`）は、ローカルで動いているサーバー（このリポなら `127.0.0.1:3000`）へ、**外向きの穴を開けずに** Cloudflare 経由で HTTPS の URL を付ける仕組みです。

- ポート開放・固定 IP・自前証明書を開発マシンに載せなくてよい
- 出てくる URL は **本番と同じく HTTPS**（共有リンク・実機テストにそのまま使える）
- 名前付きトンネルにすれば、**開発用ホスト名** を固定できる（手順は [作り方](./cloudflareトンネルの作り方.md)）

つまり第二回の時点で、

> **ローカルはローカルだが、外から見える窓だけ Cloudflare 経由で本番さながらに試せる**

という運用に寄せています。本番デプロイ（Pages / 自前サーバなど）の話はまだ先でも、**「世界に公開されるときと同じ経路（TLS・ドメイン・プロキシ）で触る」** 練習が開発フェーズからできます。

リポでは:

- `npm run dev:tunnel` — 即席トンネル（手軽に URL を発行）
- `npm run dev:tunnel:named` — 環境変数で永続トンネル
- `npm run dev:full` — 開発サーバと即席トンネルをまとめて起動

credentials や埋め済み設定は Git に載せません（[ルールブック](./ルールブック.md)）。

## 不定期に「窓を開けて」開発する

このプロジェクトの公開開発は、**いつもオンライン** ではありません。

開発者は必要なときだけ Tunnel の窓を開け、

- 共同編集者やレビュー相手に **その瞬間の localhost を HTTPS で見せる**
- スマホや別ネットワークから **本番に近い条件で** 触ってもらう
- 終わったらローカルを止め、トンネルも閉じる（常時公開のステージングを持たない選択もできる）

「ステージングサーバを月額で常時立てる」より **エコ** で、note で言っていた **不定期の公開開発** に合います。Tunnel はそのためのスイッチです。

---

第二回から `cloudflared` を入れて、**開発中のいま** から世界標準のエッジ越しに窓を開けられるようにしてあります。  
日本で知名度がまだ控えめな会社名でも、**エッジの規模と料金のバランス** ではもう当たり前の選択肢です。  
不定期で窓を開けるのは暇なときだけでいいので、見えるタイミングで URL を叩いてください。見逃したら次の窓まで待ちです（笑）。
