# godabo 개발 주체 및 활동 취지

**언어:** [日本語](./開発元.md) · [English](./Developers.md) · **한국어**

이 문서는 **공개 저장소**를 찾아오신 분을 위한 **정적 요약**입니다. *누가* godabo를 만들고 *왜* 소스를 공개하는지에만 맞춰 두었습니다. 소유·취지가 바뀔 때만 고칩니다. 회차별 상세 설명서는 일본어 `docs/`에 있으며, 긴 배경 글은 [note 연재(일본어)](https://note.com/nana_nezumi/n/nf4c8147368ae)에 실립니다.

## godabo의 목적

**godabo**는 참여형 **5W1H(누가·언제·어디서·무엇을·왜·어떻게)** 놀이의 웹 프런트입니다. 함께 채운 뒤 하나의 이야기로 감상하는 경험을 지향합니다.

일회성 데모가 아니라 **실제 서비스에 가까운 성실함**으로, 열린 상태에서 개발합니다. Git 태그(예: `note-第二回`)로 당시의 스냅샷을 따라갈 수 있게 합니다.

---

## 소스와 문서를 함께 공개하는 이유

1. **note 연재와 맞춘 공개 개발** — 코드와 재현 가능한 단계는 Git에, 긴 해설은 note에 둡니다.
2. **재현 가능성** — 태그로 「N회차 시점」을 남깁니다.
3. **경제적인 구성** — Cloudflare(Tunnel 포함)·Firebase 등, 소규모 팀도 운영 가능한 선택을 전제로 합니다.

## 제로 트러스트·개인정보·보안 (함께 나누고 싶은 것)

참여형 서비스에서는 **개인정보·인증·Room 데이터**를 어디까지 신뢰할지가 설계의 중심입니다. creathree가 **지금 검토·구현 중인 예**를 저장소와 문서에 남기고, 더 많은 분과 **정보를 맞바꾸고 싶다**는 취지입니다.

진행 중인 선택을 공개하고, 피드백과 다른안은 Issue / PR로 환영합니다.

요지만 정리하면 다음과 같습니다.

- **신뢰 경계** — 앱 내부만 안전하다고 가정하지 않습니다. 브라우저·에지(Cloudflare)·서버·Room 단위로 「어디까지 신뢰할지」를 나누는 방향입니다.
- **인증과 정책의 동행** — 로그인을 넣을 때 개인정보 처리방침·이용약관을 **함께** 두려 하며, 수집은 최소·목적에 맞게 합니다.
- **이미 저장소에서 볼 수 있는 예** — 비밀값은 Git에 넣지 않음(`.env.example`·템플릿만), Tunnel 자격 증명은 저장소 밖, 개발 노출은 상시 스테이징 대신 필요 시 Tunnel, 기본 보안 헤더·locale 검증 등.
- **인증(방향)** — 팝업보다 **리다이렉트 방식**을 선호할 예정이며, 정책 문구는 locale URL과 맞추고 릴리스·태그와 대응시킬 계획입니다.

기업의 내부 정책과 비교하는 참고 자료, 개인 프로젝트의 초안으로 쓰시면 됩니다. 법적·컴플라이언스 자문은 대체하지 않습니다.
